## The algorithm in one paragraph

Each of the K = 2 regimes has its own bank of `n_particles` particles over `(kappa, alpha)` and its own regime probability. On `update(obs)`: every particle is reweighted with the same Gaussian proxy likelihood as the validated bootstrap PF; the bank's marginal likelihood updates the regime probability (`mu_j ~ mu_prior_j * L_j`); the belief for step `t` is recorded (reweighted, pre-resample). Then the IMM interaction: the predicted regime probabilities are `mu_pred = P^T mu`, the mixing weights are `M[i,j] = P[i,j] mu_i / mu_pred_j`, and bank `j`'s particles for the next step are drawn by systematic resampling from the union of all banks' particles with weights `M[i,j] * w_i`. Roughening jitter (15% of the regime's own CIR stationary std) is added, then each bank is propagated one Euler-Maruyama CIR step with its regime's parameters (`RegimeParams.effective_cir`), followed by the bootstrap PF's alpha-jump component. With K = 1 it falls back to the bootstrap rule (ESS-triggered resampling) and is the same algorithm as `ParticleFilter`.

## Choices that are mine, not validated (all flagged in the code)

| Choice | Value | Why | How to change it from data |
|---|---|---|---|
| Particles per bank | 2000 (4000 total) | Bootstrap PF uses 5000 for one state; two banks at 2000 each keeps a live step cheap | `IMMParams.n_particles`; timing is reported |
| Resampling for K > 1 | every step (inside the mixing) | Mixing across banks requires resampling from the union | not a knob; ESS-triggered mixing is not implemented |
| `jump_prob` | 0.03 | Keeps injected shocks in the model class; smaller than the bootstrap PF's 0.08 because a jump-capable calm bank can partly imitate stress and blur regime detection | sweep `{0, 0.03, 0.08}` runs automatically |
| `obs_noise_inflation` | 1.0 | Validated Gaussian model. Stage 1 measured Hawkes residual std about 1.4x the assumed noise, so 1.4 is the value to try on those arms | sweep `{1.0, 1.4, 2.0, 3.0}` runs automatically; see (b) for what it shows on the Hawkes arm |
| Filter's regime model | TRUE `P`, TRUE per-regime CIR (Stage 0 Decision 2) | Matches how the bootstrap PF gets true CIR parameters | two misspecified runs (wrong `P`, wrong stress levels) run automatically |
| Initial bank levels | each bank starts at its own regime's level, initial std scaled by that regime's stationary std | Simulator also starts a path at the regime's own level | `reset()` |
| Regime probability floor | 1e-12 | Avoids an exact zero | `IMMParams.regime_prob_floor` |

## What the validation script checks

**HARD (pass/fail):** IMM mixing algebra (columns sum to 1, `mu_pred = P^T mu`, identity and unreachable-regime cases); `Estimator` protocol; belief contract with K = 2 at every step of every episode; ESS bounds (combined in `[1, K*n]`, per bank in `[1, n]`); determinism (same seed, also after `reset`); K = 1 IMM-PF reproduces the bootstrap PF (alpha and kappa RMSE ratio within 0.90-1.10 and alpha 90% coverage within 0.05, on 5000 particles; those tolerances are my judgement, and the observed ratios were 1.000000 because both filters draw random numbers in the same order); K = 2 mixing path with identity `P` and a one-hot prior (calm world: max p(stressed) < 1e-3; stressed world: min p(stressed) > 0.999; thresholds are my judgement); a `StepResponse` built from a real K = 2 belief passes `validate_step_response` and `json.dumps`.

**INFO (numbers, no pass/fail):** pooled alpha/kappa RMSE, bias and 90% coverage overall and by true regime, against the untouched bootstrap PF on the same observations; ESS; regime-detection report (MAP accuracy vs majority baseline, per-class recall, balanced accuracy, Brier skill, log-loss, AUC, ECE, detection rate and delay for stress onsets and recoveries at thresholds 0.5 and 0.9, steady-state false-alarm rate and recall); a controlled test (calm, 20 forced stressed steps, calm) that isolates detection delay; an injected alpha x3 shock inside the regime world; sensitivity sweeps (`jump_prob`, noise inflation 1.4/2.0/3.0, roughening 0.05, two misspecified regime models); a proxy-likelihood diagnostic (mean and sd of the standardised proxy residual at the TRUE state, per channel and regime); ms per step.

## Not built (so nobody assumes it exists)

- No likelihood on the Hawkes extras (`spread_ticks`, `n_open`, `n_events`, `hawkes_excitation`). On the Hawkes arms the Gaussian likelihood is misspecified by construction.
- No regime-specific observation model: the proxy likelihood is the same function of `(kappa, alpha)` in every bank, so regime evidence comes from the regime-specific dynamics only.
- No mid-price return input (not in the C2 contract), so the regime information in price volatility is unused.
- `P` and the per-regime CIR parameters are known, not learned.
- No "oracle-regime" filter (a filter told the true regime) as an upper bound for regime-detection quality. It would make the detection numbers easier to interpret; it is a reasonable follow-up.
- Boers & Driessen (2003) and Blom & Bar-Shalom (1988) were not re-read line by line. This is the per-mode-PF-with-mixing variant the brief asks for, in their spirit, not a transcription of either algorithm.

# HANDOFF SYNOPSIS (Stage 2)

**(a) What was built.** `src/imm_particle_filter.py`: an Interacting-Multiple-Model particle filter for the two-regime (calm/stressed) latent-liquidity world. It keeps one particle bank per regime over `(kappa_t, alpha_t)`, updates regime probabilities from each bank's marginal likelihood, mixes banks through the transition matrix `P` (IMM interaction implemented by resampling from the union of banks), and propagates each bank with its regime's CIR parameters plus the bootstrap PF's alpha-jump component. The likelihood is the validated bootstrap PF's Gaussian likelihood on the three core proxies (`spread`, `volume`, `realvol`). `src/belief_metrics.py` scores any estimator's beliefs (tracking RMSE/bias/coverage per regime, regime-detection accuracy, Brier, log-loss, AUC, reliability, detection delay, false alarms). `validation/validate_imm_pf.py` runs the checks and writes the figures and `stage2_results.md`. The validated bootstrap filter and every Stage 0/1 file are unchanged.

**(b) What the validation shows.** Source: full run of `validation/validate_imm_pf.py` (mode full, 200 episodes of N = 50 steps per arm, 10,000 steps per arm, stationary regime start, 34.6% of steps truly stressed, runtime 120 s). Full tables: `validation/outputs/stage2_results.md` and `stage2_validation_summary.json`; figures 09-11. Defaults: 2000 particles per bank, `jump_prob = 0.03`, `obs_noise_inflation = 1.0`, roughening 0.15, sigma inflation 1.5. The bootstrap PF baseline is the untouched, regime-blind filter with default `PFParams` (5000 particles) run on the same observations.

*HARD checks: 10/10 pass* (mixing algebra, `Estimator` protocol, K = 2 mixing path with identity `P` [worst wrong-regime probability 1e-12 in the calm world, 1.00 in the stressed world], belief contract and ESS bounds on every step of both arms, determinism, K = 1 regression [alpha and kappa RMSE ratios 1.000000, coverage difference 0.000000], real K = 2 `StepResponse` passes `validate_step_response` and `json.dumps`).

*Gaussian arm (the validated observation model).* Alpha RMSE 2.51e-6 (IMM) vs 1.84e-5 (bootstrap); in truly stressed steps 3.11e-6 vs 3.10e-5, in truly calm steps 2.12e-6 vs 2.84e-6. IMM has lower per-episode alpha RMSE in 96% of episodes (paired mean difference -1.1e-5, s.e. 8.6e-7). Alpha 90% coverage 0.942 (bootstrap 0.751; stressed steps 0.944 vs 0.529); kappa 90% coverage 0.953 (bootstrap 0.477). So the filter is slightly conservative (about 4 points over nominal) rather than overconfident. For scale, always guessing the calm long-run mean gives alpha RMSE 1.24e-4. Combined ESS: median 1400, minimum 6.2. Regime detection (filtered p(stressed), 10,000 steps): MAP accuracy 0.984 vs 0.653 for always predicting calm; recall calm 0.982, stressed 0.988; Brier 0.0116 (skill 0.949 vs the best constant predictor); log-loss 0.041 vs 0.645; AUC 0.999; ECE 0.005. Stress onsets (256 spells): detected 100% at threshold 0.5 (98% at 0.9), median delay 0 steps, mean delay 0.09 steps, p90 delay 0; recoveries detected 98%, median delay 0; steady-state false-alarm rate 0.2% and stressed recall 99.4% at 0.5. Controlled test (calm, forced stress on steps 20-39, calm; 40 seeds): onset detected in 100% with median delay 0, recovery declared in 100% with median delay 0, no false alarms before the window.

*Spread-Hawkes arm (Stage 1's realistic observation model).* Here the Gaussian likelihood is wrong, and the results show it. Alpha RMSE 1.01e-5 (IMM) vs 2.06e-5 (bootstrap); in stressed steps 1.37e-5 vs 3.36e-5, but in calm steps 7.5e-6 vs 7.07e-6 (no gain). **Alpha 90% coverage is 0.543 (bootstrap 0.508) and stressed-step coverage is 0.427: the filter is severely overconfident.** Alpha bias is positive in both regimes (+2.66e-6 calm, +8.39e-6 stressed). Kappa 90% coverage 0.660. Combined ESS: median 1110, minimum 1. Regime detection still works but is weaker: accuracy 0.949 (majority 0.653), balanced accuracy 0.948, Brier skill 0.823, AUC 0.987, ECE 0.021; onsets detected 98% at threshold 0.5 (96% at 0.9), median delay 0, mean delay 0.16, p90 delay 1; recoveries detected 96%; steady-calm false-alarm rate 2.7% and stressed recall 94.6% at 0.5. In the controlled test onset was detected in 100% with median delay 0, recovery with median delay 1, but 18% of episodes showed a false alarm (p(stressed) >= 0.5) before the window.

*Why the Hawkes arm is overconfident (measured, not assumed).* The proxy-likelihood diagnostic computes z = (observed proxy - proxy mean at the TRUE state) / assumed noise std. On the Gaussian arm it is mean 0.00 and sd 1.00 in every channel and regime, as it should be. On the spread-Hawkes arm the mean z is +0.30 (calm) and +1.67 (stressed) for `spread`, -0.29 and -1.65 for `volume`, +0.18 and +1.00 for `realvol`, with sd z between 1.26 and 2.23. Both spread and volume therefore point to a higher alpha than the truth, mainly in stress, which matches the positive stressed-step alpha bias. This is a bias in the observation mean (Stage 1's regime-dependent Hawkes baseline and branching shift the proxies beyond what alpha explains), plus fatter noise. Widening the assumed noise helps coverage but cannot remove a bias: alpha 90% coverage on the 60-episode sweep is 0.534 (inflation 1.0), 0.664 (1.4), 0.790 (2.0), 0.876 (3.0); alpha RMSE 9.97e-6, 9.12e-6, 8.38e-6, 8.08e-6; balanced accuracy 0.949, 0.963, 0.961, 0.948; Brier skill 0.822, 0.863, 0.865, 0.823. On the Gaussian arm the same inflation only costs accuracy (1.4: coverage 0.985, balanced accuracy 0.979; 3.0: balanced accuracy 0.946, Brier skill 0.850). For the Hawkes arm, `obs_noise_inflation = 2.0` is the best trade-off between detection and coverage in this sweep and 3.0 gives the best coverage; these were compared on the same 60 episodes and are not out-of-sample, so treat the choice as provisional. The default stays at 1.0 because it is the validated Gaussian setting.

*Other sweeps and tests (60 episodes each, Gaussian arm unless stated).* `jump_prob` 0 / 0.03 / 0.08 moves Gaussian-arm alpha RMSE by about 1% and coverage by under 0.005 (2.53e-6 / 2.55e-6 / 2.56e-6), and Hawkes-arm RMSE by up to about 7% (9.28e-6 / 9.97e-6 / 1.02e-5) and coverage by 0.02 (0.523-0.543), so it is a weak knob in this world; `roughening_frac = 0.05` changes nothing visible (coverage 0.938 vs 0.940), so per-step roughening is not the cause of the slight Gaussian over-coverage. Misspecified filter `P` (diagonal 0.90/0.90 instead of 0.96/0.92): essentially no loss on either arm (Gaussian balanced accuracy 0.985, Hawkes 0.943). Misspecified stress levels (alpha x2.0, kappa x1.3 instead of x2.5, x1.6): clear damage, Gaussian alpha RMSE 6.51e-6 and coverage 0.732, Hawkes balanced accuracy 0.910 and Brier skill 0.661. Injected alpha x3 shock at step 25 (10-step window, 60 episodes): Gaussian window RMSE 4.87e-6 (IMM) vs 5.72e-6 (bootstrap), window coverage 0.815 vs 0.762; Hawkes 1.02e-5 vs 1.18e-5, coverage 0.525 vs 0.458. The IMM is somewhat better than the bootstrap PF but window coverage is below nominal for both, so shock handling is adequate rather than solved. Update cost: 1.13 ms per step on the Gaussian arm and 1.12 ms on the Hawkes arm (2 x 2000 particles, single thread, including belief construction).

*What these numbers do not show.* They come from a simulator with illustrative, uncalibrated parameters and a filter that knows the true regime model. Detection is much easier here than it would be on real data: at a switch the regime-specific mean reversion moves alpha by many noise standard deviations in one step. Performance under wrong stress levels (above) is the more honest guide to robustness. The Hawkes-arm results are a demonstration that the Gaussian likelihood is inadequate there, not a finished estimator for that arm.

**(c) Interface produced.**
`IMMParticleFilter(sim_params: SimParams, obs_params: ObsParams, regime_params: RegimeParams, imm_params: IMMParams | None = None, seed: int | None = None)`.
- `reset(seed=None)`, `update(obs) -> BeliefState` (implements `interfaces.Estimator`); `obs` is an `interfaces.Observation` (only `core_dict()` is read) or a dict with `spread/volume/realvol`. Call once per step in time order. `run(obs_df)` filters a whole observation DataFrame. `beliefs` holds every belief since `reset`. `next_regime_probs` is `p(s_{t+1} | y_0..y_t)`.
- Seed convention: use `interfaces.seed_streams(seed)["filter"]`.
- `BeliefState` per step (K = 2): `t`; `regime_probs = [p_calm, p_stressed]` = filtered `p(s_t | y_0..y_t)`, sums to 1; `kappa_mean/std`, `alpha_mean/std` = moments of the mixture over regimes (std includes between-regime spread); `ess` = ESS of the combined weighted set `1 / sum_j sum_i (mu_j w_ji)^2`, in `[1, K*n_particles]`; `per_regime = [RegimeBelief(regime, prob, kappa_mean, kappa_std, alpha_mean, alpha_std, ess)]` conditional on each regime; `n_particles = K * n_per_bank`; `loglik_increment = log p(y_t | y_0..y_{t-1})`. `to_vector()` = `[alpha_mean, alpha_std, kappa_mean, kappa_std, p_calm, p_stressed]`, raw units. Values are plain Python floats, JSON-serialisable via `dataclasses.asdict`, and a `StepResponse` with this belief is checked against `validate_step_response`.
- Timing: `belief.t = obs.t`; the belief for step `t` is the reweighted pre-resample posterior, consistent with the Stage 0 convention and with the bootstrap PF.
- Metrics: `belief_metrics.regime_detection_report(p1_list, reg_list)` and `TrackingPool` take arrays and are filter-agnostic, so Person 4 can score every estimator identically.

**(d) Assumptions, simplifications, open questions.**
1. **Defaults are reasoned, not tuned** (2000 particles per bank, `jump_prob = 0.03`, `obs_noise_inflation = 1.0`, roughening 0.15, sigma inflation 1.5), and the K = 1 and identity-`P` tolerances are my judgement. The sweeps in (b) use the same episodes for every configuration, so any choice made from them is in-sample. The slight Gaussian over-coverage (about 4 points) is not caused by roughening (sweep shows no effect); the remaining candidate is the 1.5x process-noise inflation inherited from the bootstrap PF, which was not isolated.
2. **The filter is told the true regime model** (`P`, per-regime CIR, `init_probs`; Stage 0 Decision 2, awaiting ratification). Results are therefore flattering relative to a real deployment; the two misspecified-model sweeps quantify how much.
3. **Likelihood is misspecified on the Hawkes arms, and it matters.** Measured: proxy residuals have mean z up to +1.67 / -1.65 (spread / volume, stressed) and sd z up to 2.2, and alpha 90% coverage is 0.54 (see (b)). This is a bias as well as a scale error, so noise inflation only partly repairs it (coverage 0.79 at 2.0, 0.88 at 3.0). A proper fix needs either regime-specific proxy means and scales per bank (estimated from Stage 1 simulator runs, which is a known-model assumption like Decision 2) or a likelihood on the Hawkes extras (`spread_ticks`, `n_events`, ...). Neither is built. **Persons 3 and 4: any result trained or evaluated on the Hawkes arm inherits this overconfidence unless `obs_noise_inflation` is raised, and the `alpha_std` fed to an uncertainty bonus is too small there.**
4. **Regime detection is easy in this world, so do not over-read it.** With the true regime model known, detection is 98.4% accurate with median delay 0 on the Gaussian arm and 94.9% on the Hawkes arm. Stage 1 measured that realised alpha only reaches about 1.49x its calm level in stress (against 2.5x long-run) and that calm periods on the Hawkes arm carry post-stress contamination (which fits the 2.7% steady-calm false-alarm rate there), yet the change in mean reversion still gives a strong one-step signal. With a wrong stress level (alpha x2.0 instead of x2.5) Hawkes-arm balanced accuracy falls to 0.910. There is no oracle-regime filter to say how close the IMM is to the best possible detection.
5. **Regime evidence comes only from the regime-specific dynamics**; the price return (which carries a strong regime signal in this simulator) is not in the C2 contract. Open question for Person 1 / Stage 0: add an optional return channel?
6. **Resampling every step for K > 1** is inherent to the mixing implementation and adds roughening noise every step (15% of the regime's stationary std). The `roughening_frac = 0.05` sweep shows no visible change in accuracy or coverage, so it is not a practical problem here. The inactive regime's bank routinely has a small ESS (visible in figure 10 panel c); the combined ESS stays large except at abrupt changes (Gaussian min 6.2; Hawkes min 1, a symptom of the misspecified likelihood).
7. **`jump_prob` turned out to be a weak knob** (Gaussian: RMSE within about 1%; Hawkes: RMSE within about 7%, coverage within 0.02, detection essentially unchanged), so 0.03 is reasonable for Stage 3 training. Injected-shock window coverage is 0.815 (Gaussian) and 0.525 (Hawkes), below nominal for both filters; shock handling is not solved.
8. **v1 Hawkes** has the look-ahead flagged in Stage 0 and is excluded from the default validation arms.
9. **Person 3:** `regime_probs` are filtered, not predicted; use `next_regime_probs` if a forecast is wanted. `alpha_std` widens when the regime is uncertain because it includes between-regime spread; if the uncertainty bonus should isolate within-regime posterior variance, use `per_regime[j].alpha_std` weighted by `prob` instead (a Stage 3 design decision, not settled here).
10. **Person 4:** scoring functions live in `src/belief_metrics.py`; `interfaces.paired_metrics` and `validate_interfaces.py` were not changed (the latter still tests only the K = 1 bootstrap belief and could gain an IMM case; `validate_imm_pf.py` already checks a real K = 2 `StepResponse`). `loglik_increment` is `None` (not NaN) if a step is degenerate, so `json.dumps` output stays valid. In `belief_metrics.spell_detection_stats`, spells that run to the end of an episode count as detected only if the filter declared them before the episode ended; this affects very few spells and is why `detect_rate_len_ge5` is also reported.
11. **Open follow-ups (not done):** an oracle-regime filter as an upper bound; regime-specific proxy means/scales or a Hawkes-extras likelihood for the Hawkes arm; an optional mid-price-return channel in C2; isolating the 1.5x process-noise inflation's effect on the slight over-coverage.
